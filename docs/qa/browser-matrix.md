## 手测步骤

1. 运行 `pnpm build`，在浏览器加载 `.output/chrome-mv3`。
2. 点击扩展图标两次，确认只存在一个 `timeline.html` 标签页，第二次点击会激活已有标签页。
3. 打开设置，添加 Codeforces handle，确认只弹出 Codeforces 的可选站点权限。
4. 返回 Timeline，确认先显示缓存，再执行同步；重复点击手动同步不会并发产生多次请求。
5. 断开或模拟单个来源失败，确认其他来源记录仍显示、旧缓存保留、页面出现可理解的失败提示。
6. 关闭并重启浏览器，确认本地记录仍在；删除账号后确认该账号的提交和同步状态被删除。
7. 在设置中选择 Luogu，使用当前浏览器登录态或手动 Cookie，点击“授权并添加”。
8. 确认身份授权与采集独立：已有浏览器登录态不会因授权自动打开站点；无提交、首次采集部分完成/失败仍保留有效账号及原启用选择。
9. 注销洛谷后再次同步，确认提示重新登录且旧缓存仍保留。
10. 检查扩展详情页权限，与 manifest audit 一致；Cookie 读取仅用于已授予站点，不含 `webRequest`、`scripting` 或 `<all_urls>`。
11. 在 Hydro 测试实例分别输入根地址和 `/d/student/` 地址，点击“授权并重新检测”，确认只申请纯网站 origin；`/d/student/record` 等非法页面地址不会申请权限。
12. 密码登录后确认手动实例名字/域图标、普通记录、比赛/作业标签和活动链接；仅选择最近 35 天内有提交的窗口测试活动，不要求采集更旧历史。
13. 检查同步详情中的具体活动名称和结果；单个比赛/作业记录页 403 静默跳过，不显示拒绝警告，仍计入已处理进度并保留其他记录。仅有此类拒绝时不显示未完整同步；401/登录页、429、网络和解析失败仍提示，活动发现及普通记录列表 403 不静默忽略。
14. 同身份同域再次授权不产生第二个账号；两个实例或同实例两个域的同 UID 绑定、记录和图标缓存彼此隔离，删除一个不影响另一个。
15. 删除账号或替换认证方式时同时同步，确认旧结果不会回写；重启扩展后凭证只用于重新登录，不出现在公开状态响应。

## 同步升级专项验收（全部待验证）

Chrome 和 Edge 分别记录版本、扩展构建与脱敏 Network 时间戳；不对真实 OJ 循环压测。

- [ ] 默认/首次采集为最近 7 天；固定历史 to 不移动；非法、反向、未来或早于最近 35 天范围在采集网络请求前被拒绝。
- [ ] since/until 端点保留，前后 1ms 排除；范围外详情请求为零，新结果不含范围外记录，旧缓存保留。
- [ ] 倒序第一页全晚于 until 时继续定位，跨可靠 since 边界后不发下一页；未知时间顺序不能提前判完整。
- [ ] 同 origin 连续页、新账号/新活动首页均额外等待 1000–2000ms；不同 origin 可并行；最后一页无额外等待。
- [ ] Hydro 普通/活动共享页数和唯一记录预算，用完不继续逐活动探测，未访问活动显示缺口。
- [ ] 429 响应头返回后禁止同 origin 新尝试；Retry-After 秒数/日期有效；force 无法绕过；不同 Hydro 实例及 kenkoooo.com/atcoder.jp 隔离。
- [ ] 同浏览器会话内重启 service worker，仍从 storage.session 恢复冷却；storage.session 不可用时后台日志报告降级，内存冷却继续有效。
- [ ] 排队、sleep、HTTP 与 Cookie 恢复期间取消不会使下一请求提前执行或混用凭证；新凭证旧任务结果不能回写。
- [ ] 不同窗口按账号串行，容量外显示 busy；partial 后普通同步短期不重复抓取，手动 force 仍遵守网络规则。
- [ ] 部分结果即使有记录也显示 partial；缺 coverage 显示未知；详情/品牌失败仅提示补全；长事件被 worker 中断时不显示成功。
- [ ] AtCoder 空入选集不请求题名表/详情，详情 429 后不领取新任务；CF 满 1000 条未到窗口时显示 partial。
- [ ] AtCoder 有效空批或不足 500 条的批次显示 complete；满批按尾秒包含式游标翻页并去重，跨 until 后停止；同秒满批无法前进时显示未验证，不无限翻页。
