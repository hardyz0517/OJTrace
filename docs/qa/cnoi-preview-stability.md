# CNOI 实时预览稳定性修复

日期：2026-10-19。

## 原因与行为

原先每次输入后，新的输入 key 都与上次转换结果不一致。组件立即在编辑器前插入「结果已过期」横幅，250ms 防抖及转换完成后再删除，导致两侧编辑器反复上下移动。每次按键还会将正在编辑的 Source 与旧输出重新计算差异，可能产生不属于同一转换的标记。

现改为：

- 删除正常等待时的过期横幅及标题变色；工具栏已有状态位置保持固定最小宽度和行高，仅显示「预览待更新」。快速转换不闪现忙碌提示，实际请求超过 500ms 才显示「正在转换」。
- 仍使用 250ms 防抖及真实后台 Transformer。编辑时保留上次成功输出；差异使用该成功结果捕获的 Source 快照计算。Source 已改变时暂时隐藏旧 Source 行标记，成功后同步更新，不拿新输入与旧输出作比较。
- 转换失败、超时及重试放在编辑器下方的诊断区域，不向编辑器上方插入新元素。失败保留上次成功输出；已过期的结构提示明确标注为「上次结果」。
- 新的 useConversionPreview 负责请求生命周期：输入提交即失效旧请求；乱序成功、旧错误、中文输入期间的响应、非法规则草稿期间的响应、其他 OJ 的结果均不会覆盖当前显示。
- 15 秒请求超时后允许主动重试；超时结果即便稍后返回也不再提交。此机制只终止前端等待，后台已发出的请求无法通过当前消息协议强行中断。
- OJ 切换不继承其他 OJ 的输入法组合状态；转换 key 不包含案例名称/ID，对相同值的新规则对象不重复发起请求。撤销回曾经失败的输入时，不重新显示旧请求的错误。
